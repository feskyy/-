```rust
//! hello_solana — первая Solana Program (неделя 4, РО2).
//!
//! Программа в Solana хранит только код. Данные живут в отдельных аккаунтах,
//! которые вызывающий передаёт программе. Здесь аккаунты не нужны: программа
//! только пишет сообщения в лог транзакции.
//!
//! Формат instruction_data:
//!   [0]            -> Hello: пишет приветствие и Program ID
//!   [1, <utf-8>…]  -> Echo: пишет в лог текст, присланный клиентом

use solana_program::{
    account_info::AccountInfo, entrypoint, entrypoint::ProgramResult, msg,
    program_error::ProgramError, pubkey::Pubkey,
};

// Единственная точка входа: рантайм Solana вызывает process_instruction.
entrypoint!(process_instruction);

/// Максимальная длина текста для Echo (байт). Защита от слишком больших логов.
pub const MAX_ECHO_LEN: usize = 128;

/// Инструкции программы. Первый байт instruction_data — номер варианта.
#[derive(Debug, PartialEq, Eq)]
pub enum HelloInstruction<'a> {
    /// Тег 0
    Hello,
    /// Тег 1 + UTF-8 текст
    Echo(&'a str),
}

impl<'a> HelloInstruction<'a> {
    /// Разбирает байты инструкции. Любая ошибка формата -> InvalidInstructionData.
    pub fn unpack(data: &'a [u8]) -> Result<Self, ProgramError> {
        let (&tag, rest) = data
            .split_first()
            .ok_or(ProgramError::InvalidInstructionData)?;

        match tag {
            0 => Ok(Self::Hello),
            1 => {
                if rest.len() > MAX_ECHO_LEN {
                    return Err(ProgramError::InvalidInstructionData);
                }
                let text = core::str::from_utf8(rest)
                    .map_err(|_| ProgramError::InvalidInstructionData)?;
                Ok(Self::Echo(text))
            }
            _ => Err(ProgramError::InvalidInstructionData),
        }
    }
}

/// Точка входа программы.
/// - program_id: адрес этой программы (Program ID)
/// - accounts: аккаунты, переданные в инструкции (здесь не используются)
/// - instruction_data: байты инструкции
pub fn process_instruction(
    program_id: &Pubkey,
    accounts: &[AccountInfo],
    instruction_data: &[u8],
) -> ProgramResult {
    match HelloInstruction::unpack(instruction_data)? {
        HelloInstruction::Hello => {
            msg!("Hello, Solana! Program ID: {}", program_id);
            msg!("Accounts passed: {}", accounts.len());
        }
        HelloInstruction::Echo(text) => {
            msg!("Echo: {}", text);
        }
    }
    Ok(())
}
```

**Что делает код:** первая инструкция (`0`) пишет приветствие и Program ID в лог; вторая (`1` + текст) пишет в лог текст от клиента. Первый байт данных выбирает инструкцию.

### Подготовка к защите (неделя 4)
- **Почему программа не хранит данные?** Код и данные в Solana разделены. Программа это исполняемый аккаунт, а данные лежат в других аккаунтах, которые передаёт вызывающий. Так сеть заранее знает, какие аккаунты читаются и пишутся, и может исполнять разные транзакции параллельно. Наша программа аккаунты вообще не использует.
- **Что такое Program ID?** Адрес (публичный ключ) аккаунта программы. Клиент указывает его в транзакции, чтобы сеть знала, чей код вызвать.
- **Что делает `entrypoint!`?** Создаёт единственную точку входа, которую вызывает рантайм, и передаёт данные в `process_instruction`.
- **Зачем тег в первом байте?** Точка входа одна, поэтому тип инструкции кодируется в данных; `match` выбирает ветку.
- **Что при неизвестном теге?** Ошибка `InvalidInstructionData`, транзакция отклоняется.

### Шаг 2. Код программы
Откройте `src/lib.rs`. **Оставьте две верхние строки шаблона** (`use anchor_lang::prelude::*;` и `declare_id!("...")`, ID в ней ваш и обновится при сборке). Всё, что ниже `declare_id!`, удалите и вставьте:

```rust
#[program]
pub mod counter {
    use super::*;

    /// Создаёт аккаунт Counter и обнуляет счётчик.
    pub fn initialize(ctx: Context<Initialize>) -> Result<()> {
        let counter = &mut ctx.accounts.counter;
        counter.count = 0;
        msg!("Counter создан, count = {}", counter.count);
        Ok(())
    }

    /// Увеличивает счётчик на 1.
    pub fn increment(ctx: Context<Increment>) -> Result<()> {
        let counter = &mut ctx.accounts.counter;
        counter.count = counter
            .count
            .checked_add(1)
            .ok_or(CounterError::Overflow)?;
        msg!("Counter увеличен, count = {}", counter.count);
        Ok(())
    }
}

#[derive(Accounts)]
pub struct Initialize<'info> {
    // 8 байт — discriminator Anchor, ещё 8 — поле count (u64)
    #[account(init, payer = user, space = 8 + 8)]
    pub counter: Account<'info, Counter>,
    #[account(mut)]
    pub user: Signer<'info>,
    pub system_program: Program<'info, System>,
}

#[derive(Accounts)]
pub struct Increment<'info> {
    // mut: инструкция изменяет данные аккаунта
    #[account(mut)]
    pub counter: Account<'info, Counter>,
}

#[account]
pub struct Counter {
    pub count: u64,
}

#[error_code]
pub enum CounterError {
    #[msg("Переполнение счётчика")]
    Overflow,
}
```

**Что здесь важно:**
- `#[account] struct Counter` — состояние (поле `count`).
- `space = 8 + 8` — 8 байт discriminator Anchor и 8 байт под `u64`.
- `#[account(mut)]` у `counter` в `Increment` — потому что инструкция меняет данные.
- `checked_add` — защита от переполнения.

### Подготовка к защите (неделя 5)
- **Что Anchor делает за вас?** Разбирает аккаунты в именованные структуры, проверяет ограничения (`mut`, `signer`, `init`, владелец, discriminator), сериализует данные, вызывает инструкции по имени и генерирует IDL.
- **Зачем IDL?** JSON-описание интерфейса программы: инструкции, аккаунты, аргументы, типы. Клиент по нему собирает транзакции и читает аккаунты.
- **Что такое discriminator?** Первые 8 байт аккаунта с идентификатором типа; Anchor проверяет его при чтении.
- **Почему `space = 8 + 8`?** 8 байт discriminator + 8 байт `u64`.
- **Зачем `mut`?** Рантайм не позволяет менять аккаунты, не помеченные как изменяемые.

```rust
/// Максимальные длины в БАЙТАХ (для кириллицы 1 символ = 2 байта).
pub const MAX_USERNAME_LEN: usize = 32;
pub const MAX_BIO_LEN: usize = 160;

#[program]
pub mod profile {
    use super::*;

    /// Создаёт профиль PDA для кошелька user. Повторное создание невозможно:
    /// аккаунт с таким адресом уже существует, `init` вернёт ошибку.
    pub fn create_profile(
        ctx: Context<CreateProfile>,
        username: String,
        bio: String,
    ) -> Result<()> {
        validate(&username, &bio)?;
        let profile = &mut ctx.accounts.profile;
        profile.authority = ctx.accounts.user.key();
        profile.username = username;
        profile.bio = bio;
        profile.created_at = Clock::get()?.unix_timestamp;
        profile.bump = ctx.bumps.profile;
        msg!("Профиль создан для {}", profile.authority);
        Ok(())
    }

    /// Обновляет username и bio. Только владелец (has_one + Signer).
    pub fn update_profile(
        ctx: Context<UpdateProfile>,
        username: String,
        bio: String,
    ) -> Result<()> {
        validate(&username, &bio)?;
        let profile = &mut ctx.accounts.profile;
        profile.username = username;
        profile.bio = bio;
        msg!("Профиль обновлён");
        Ok(())
    }

    /// Закрывает профиль: рента возвращается владельцу (close = authority).
    pub fn close_profile(_ctx: Context<CloseProfile>) -> Result<()> {
        msg!("Профиль закрыт");
        Ok(())
    }
}

/// Проверка длин. Выделена в функцию, чтобы тестироваться без сети.
pub fn validate(username: &str, bio: &str) -> Result<()> {
    require!(!username.is_empty(), ProfileError::UsernameEmpty);
    require!(username.len() <= MAX_USERNAME_LEN, ProfileError::UsernameTooLong);
    require!(bio.len() <= MAX_BIO_LEN, ProfileError::BioTooLong);
    Ok(())
}

#[derive(Accounts)]
pub struct CreateProfile<'info> {
    // seeds = ["profile", кошелёк] -> один пользователь = один профиль.
    // Клиент обязан использовать точно такие же seeds.
    #[account(
        init,
        payer = user,
        space = 8 + Profile::INIT_SPACE,
        seeds = [b"profile", user.key().as_ref()],
        bump
    )]
    pub profile: Account<'info, Profile>,
    #[account(mut)]
    pub user: Signer<'info>,
    pub system_program: Program<'info, System>,
}

#[derive(Accounts)]
pub struct UpdateProfile<'info> {
    // seeds берём из profile.authority; has_one сверяет его с подписантом authority
    #[account(
        mut,
        seeds = [b"profile", profile.authority.as_ref()],
        bump = profile.bump,
        has_one = authority
    )]
    pub profile: Account<'info, Profile>,
    pub authority: Signer<'info>,
}

#[derive(Accounts)]
pub struct CloseProfile<'info> {
    #[account(
        mut,
        seeds = [b"profile", profile.authority.as_ref()],
        bump = profile.bump,
        has_one = authority,
        close = authority
    )]
    pub profile: Account<'info, Profile>,
    #[account(mut)]
    pub authority: Signer<'info>,
}

#[account]
#[derive(InitSpace)]
pub struct Profile {
    pub authority: Pubkey, // 32
    #[max_len(32)]
    pub username: String, // 4 + 32
    #[max_len(160)]
    pub bio: String, // 4 + 160
    pub created_at: i64, // 8
    pub bump: u8, // 1
}

#[error_code]
pub enum ProfileError {
    #[msg("Username не может быть пустым")]
    UsernameEmpty,
    #[msg("Username длиннее 32 байт")]
    UsernameTooLong,
    #[msg("Bio длиннее 160 байт")]
    BioTooLong,
}
```

**Что здесь важно:**
- `seeds = [b"profile", кошелёк]` — адрес профиля (PDA) вычисляется из текста `"profile"` и адреса кошелька. Поэтому один кошелёк = один профиль, а адрес можно вычислить заранее.
- `space = 8 + Profile::INIT_SPACE` = 249 байт (строки считаются как 4 + макс. длина).
- Длины считаются в **байтах**: русская буква занимает 2 байта, поэтому 16 русских букв это уже 32 байта.
- `has_one = authority` + `Signer` — править профиль может только владелец.
- `close = authority` — при закрытии SOL возвращаются владельцу.

````
# Неделя 6. On-chain профиль на PDA

Курс «ИТ-стартап. Итоговый проект 1», РО2. Лабораторная работа 6.

## Что это
Программа на Anchor: каждый кошелёк имеет ровно один профиль — аккаунт-PDA.

Аккаунт `Profile`: `authority` (Pubkey владельца), `username` (≤ 32 байт), `bio` (≤ 160 байт),
`created_at` (unix time), `bump`.

Инструкции: `create_profile`, `update_profile`, `close_profile` (возвращает ренту владельцу).

## Seeds и почему
`seeds = [b"profile", wallet_pubkey]`
- префикс `"profile"` отделяет профили от других PDA программы;
- кошелёк делает адрес уникальным для пользователя и **предсказуемым**: любой клиент
  вычислит адрес профиля по одному кошельку, база данных не нужна;
- «один кошелёк — один профиль» обеспечивается самим адресом: второй `init` по тому же адресу падает.

## Размер аккаунта
8 (discriminator) + 32 (authority) + 4+32 (username) + 4+160 (bio) + 8 (created_at) + 1 (bump) = **249 байт**
(в коде `8 + Profile::INIT_SPACE`). Длины считаются в БАЙТАХ: кириллица занимает 2 байта на символ.

## Безопасность
- `update_profile` и `close_profile`: `has_one = authority` + `Signer` — править профиль может только владелец;
- seeds и `bump` хранятся/проверяются, поэтому подсунуть чужой аккаунт нельзя;
- проверки длин → понятные ошибки `UsernameEmpty`, `UsernameTooLong`, `BioTooLong`.
````

### Подготовка к защите (неделя 6)
- **Почему у PDA нет приватного ключа?** Адрес PDA выбирается так, чтобы он не лежал на кривой Ed25519, поэтому секретного ключа для него не существует. Подписать за него может только программа, вычислившая его. Аккаунтом PDA «владеет» программа.
- **Как клиент находит чужой профиль по одному кошельку?** Вычисляет адрес теми же seeds и Program ID (`findProgramAddressSync([Buffer.from("profile"), wallet.toBuffer()], programId)`) и читает аккаунт. База данных не нужна.
- **Зачем `bump`?** Число, которое «выводит» адрес за пределы кривой. Сохранённый bump экономит вычисления.
- **Что делает `has_one = authority`?** Сверяет поле `authority` в аккаунте профиля с подписантом транзакции.
- **Почему повторное создание падает?** Аккаунт по этому адресу уже существует.

```ts
// Шаг 2: создаёт Mint на Token-2022 с расширением Metadata (name, symbol, uri).
import { Keypair, SystemProgram, Transaction, sendAndConfirmTransaction } from "@solana/web3.js";
import {
  ExtensionType,
  LENGTH_SIZE,
  TOKEN_2022_PROGRAM_ID,
  TYPE_SIZE,
  createInitializeMetadataPointerInstruction,
  createInitializeMintInstruction,
  getMintLen,
} from "@solana/spl-token";
import { TokenMetadata, createInitializeInstruction, pack } from "@solana/spl-token-metadata";
import { DECIMALS, TOKEN_NAME, TOKEN_SYMBOL, TOKEN_URI } from "./config";
import { addrLink, connection, loadKeypair, txLink, writeState } from "./common";

async function main() {
  const payer = loadKeypair("wallet1.json");
  const mintKp = Keypair.generate();
  const mint = mintKp.publicKey;

  const metadata: TokenMetadata = {
    mint,
    name: TOKEN_NAME,
    symbol: TOKEN_SYMBOL,
    uri: TOKEN_URI,
    additionalMetadata: [],
  };

  // Размер: сам mint + указатель на метаданные; затем данные метаданных
  const mintLen = getMintLen([ExtensionType.MetadataPointer]);
  const metadataLen = TYPE_SIZE + LENGTH_SIZE + pack(metadata).length;
  const lamports = await connection.getMinimumBalanceForRentExemption(mintLen + metadataLen);

  const tx = new Transaction().add(
    SystemProgram.createAccount({
      fromPubkey: payer.publicKey,
      newAccountPubkey: mint,
      space: mintLen,
      lamports,
      programId: TOKEN_2022_PROGRAM_ID, // Token-2022, не классическая Token Program!
    }),
    // метаданные хранятся в самом mint-аккаунте
    createInitializeMetadataPointerInstruction(mint, payer.publicKey, mint, TOKEN_2022_PROGRAM_ID),
    createInitializeMintInstruction(mint, DECIMALS, payer.publicKey, null, TOKEN_2022_PROGRAM_ID),
    createInitializeInstruction({
      programId: TOKEN_2022_PROGRAM_ID,
      mint,
      metadata: mint,
      name: metadata.name,
      symbol: metadata.symbol,
      uri: metadata.uri,
      mintAuthority: payer.publicKey,
      updateAuthority: payer.publicKey,
    })
  );

  const sig = await sendAndConfirmTransaction(connection, tx, [payer, mintKp]);
  writeState({ mint: mint.toBase58() });

  console.log("Mint создан:", mint.toBase58());
  console.log("Explorer mint:", addrLink(mint));
  console.log("Транзакция:   ", txLink(sig));
}

main().catch((e) => { console.error("Ошибка:", e.message ?? e); process.exit(1); });
```

```ts
// БОНУС: выпуск и перевод токена с комиссией (mint из bonus-02).
import {
  TOKEN_2022_PROGRAM_ID,
  getAccount,
  getOrCreateAssociatedTokenAccount,
  mintTo,
  transferCheckedWithFee,
} from "@solana/spl-token";
import { DECIMALS, FEE_BASIS_POINTS, MAX_FEE_TOKENS, MINT_AMOUNT_TOKENS, TRANSFER_AMOUNT_TOKENS } from "./config";
import { connection, loadKeypair, requireMint, txLink } from "./common";

async function main() {
  const owner = loadKeypair("wallet1.json");
  const receiver = loadKeypair("wallet2.json");
  const mint = requireMint("mintWithFee");
  const unit = 10n ** BigInt(DECIMALS);

  const src = await getOrCreateAssociatedTokenAccount(
    connection, owner, mint, owner.publicKey, false, undefined, undefined, TOKEN_2022_PROGRAM_ID
  );
  const dst = await getOrCreateAssociatedTokenAccount(
    connection, owner, mint, receiver.publicKey, false, undefined, undefined, TOKEN_2022_PROGRAM_ID
  );

  await mintTo(connection, owner, mint, src.address, owner, MINT_AMOUNT_TOKENS * unit,
    [], undefined, TOKEN_2022_PROGRAM_ID);

  const amount = TRANSFER_AMOUNT_TOKENS * unit;
  // комиссия = amount * bps / 10000 (с округлением вверх), но не больше максимума
  let fee = (amount * BigInt(FEE_BASIS_POINTS) + 9999n) / 10000n;
  const maxFee = MAX_FEE_TOKENS * unit;
  if (fee > maxFee) fee = maxFee;

  const sig = await transferCheckedWithFee(
    connection, owner, src.address, mint, dst.address, owner, amount, DECIMALS, fee,
    [], undefined, TOKEN_2022_PROGRAM_ID
  );
  const received = await getAccount(connection, dst.address, "confirmed", TOKEN_2022_PROGRAM_ID);
  console.log(`Отправлено ${amount} мин. ед., комиссия ${fee}, получатель получил ${received.amount}`);
  console.log("Транзакция:", txLink(sig));
}
```

### Подготовка к защите (неделя 7)
- **Чем Mint отличается от Token Account?** Mint это описание токена (decimals, mint authority, метаданные, общий supply). Token Account хранит баланс конкретного владельца; обычно используют ассоциированный (ATA), чей адрес вычисляется из кошелька и mint.
- **Что даёт Token-2022 по сравнению с классическим токеном?** Расширения: метаданные прямо в mint, комиссия за перевод, запрет передачи и другие. Адрес программы другой (`TOKEN_2022_PROGRAM_ID`).
- **Что такое decimals?** Количество знаков после запятой. При 6 знаках 1 токен = 1 000 000 минимальных единиц, поэтому в коде умножаем на `10n ** 6n`.
- **Зачем ATA у получателя?** Баланс хранится в токен-аккаунте; без него переводить некуда. Скрипт создаёт ATA получателя перед переводом.
- **Что будет, если потерять mint authority?** Больше нельзя выпускать токены.
- **Что такое metadata pointer?** Расширение, указывающее, где лежат метаданные (здесь в самом mint-аккаунте).

> **Заметка по силлабусу.** CPI (вызов одной программы другой) изучается на неделе 11, а токены создаются именно через вызовы Token Program. Сейчас достаточно клиентских библиотек, внутреннее устройство разберёте позже.
